\chapter*{Abstract}
\addcontentsline{toc}{chapter}{Abstract}
People often listen to music, podcasts and audiobooks, but keeping track of saved and unfinished content across audio applications can be inconvenient. This project explored how these different types of audio could be organised in one interface without making navigation confusing. We developed Omnisound, a desktop-first web prototype with shared search, a Library for saved items and a Continue Listening section for unfinished audio.

We began with a project concept and paper sketches, then built an interactive first prototype (V1). We tested it with three students using three tasks: finding and saving Weezer, resuming an unfinished audiobook and browsing podcasts. We recorded task completion, time, navigation routes and participant comments. Based on the observations, we created a second prototype (V2) with a smaller Home banner, a more noticeable Continue Listening section and clearer Save/Saved controls. Three new students tested V2 using the same tasks.

All nine task attempts were completed in each round without direct help. However, only one of three V1 participants used Continue Listening directly, compared with all three V2 participants. The average time for resuming the audiobook was 27.0 seconds in V1 and 13.3 seconds in V2. The other tasks also had shorter recorded times in the second round.

The results suggest that the changes made unfinished audio easier to find for these participants. Because the tests involved small, different groups and a limited prototype, further testing is needed before drawing wider conclusions. The project shows how watching users complete real tasks can guide practical improvements to an interface.
